# Foodie v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Portare Foodie a circa 100 ricette e aggiungere voto del giorno, serie, allenamenti segnati, medaglie, azioni rapide nel diario, spesa per reparto e backup.

**Architecture:** App a file unico. Il sorgente diventa `src/app.html` (formato artifact: niente `<html>/<head>/<body>`), uno script Python lo avvolge in `index.html` per GitHub Pages aggiungendo manifest e service worker. I test girano con Playwright sul file generato e chiamano direttamente le funzioni globali della pagina.

**Tech Stack:** HTML/CSS/JS senza librerie, Python 3 per la build, Node + Playwright (già installato) per i test.

**Spec:** `docs/superpowers/specs/2026-11-24-foodie-v2-design.md`

## Global Constraints

- Nessuna libreria esterna, nessuna richiesta di rete a parte Google Fonts.
- Dati solo in `localStorage`, chiavi con prefisso `pp.`; letture e scritture sempre in try/catch tramite `store.get/store.set`.
- Nessuna ricetta con maiale, strutto, salumi di maiale o gelatina.
- Testi dell'interfaccia in italiano, tono incoraggiante.
- Ogni colore da token CSS, definito in `:root` e nei due blocchi scuri.
- Larghezza 400 px senza scroll orizzontale; pulsanti con sfondo pieno distinguibile.
- Ogni modifica a `src/app.html` è seguita da `python3 -I tools/build.py` (incrementa la versione `foodie-vN` in `sw.js`).

## Review Focus

1. Dati salvati dalla versione precedente (piano con ricette vecchie, diario senza campo `train`, nessuna chiave `badges`): l'app deve aprirsi senza errori e senza perdere nulla.
2. Importare un backup non valido o di un'altra app: messaggio chiaro, dati attuali intatti.
3. Giorni senza pasti registrati nel mezzo della serie: la serie si interrompe ma il voto non diventa 0, resta "nessun voto".
4. Profilo vegano o vegetariano con le nuove ricette: il piano deve trovare ricette per ogni pasto.
5. Medaglie: non devono comparire due volte né sbloccarsi con i dati di esempio del primo avvio.

Ogni punto ha il suo test nel task che possiede il codice (contrassegnato **[RF n]**).

### Task 6: Voto del giorno, serie e allenamenti

**Files:** Modify `src/app.html` (`viewOggi`, `weekBlock`, `viewPiano`, `viewAllenamento`); Test.

**Interfaces:**
- Produces: `dayScore(L:{items,water,train?}, c:calc(), isTrainDay:boolean) -> null | {score:int, parts:{kcal,prot,water,fibre,train}}`
  - `null` se `L.items.length===0`.
  - kcal (30): pieno se |tot−target| ≤ 10% del target, 0 se ≥ 40%, lineare in mezzo.
  - prot (25): `25*min(1, p/c.prot)`.
  - water (15): `15*min(1, water/8)`.
  - fibre (15): conta gli item con fibre (ricette con `mi` che include `fibre`, oppure item del calcolatore con `fib>=3`); pieno da 3 in su, 5 punti per item.
  - train (15): pieno se `L.train` è valorizzato o se `!isTrainDay`; altrimenti 0.
  - Gli item del calcolatore salvano `fib` (aggiungere in `addtxt`).
- Produces: `isTrainDay(date:Date) -> boolean` (lunedì, mercoledì, venerdì, come la scheda).
- Produces: `streaks(todayKey) -> {logged:int, good:int}`: giorni consecutivi con item, contando all'indietro da oggi (da ieri se oggi è vuoto); `good` = consecutivi con voto ≥ 70.
- Produces: `setTrain(dateKey, kind:'A'|'B'|'altro'|null)` → `log[k].train`; `weekTrainCount(date) -> int` da lunedì a domenica.
- UI: in Oggi un anello con il voto (SVG, colore verde ≥70, giallo 40–69, arancio <40) e le 5 voci; chip con icona fiamma (SVG) e "Serie: N giorni"; in Allenati e in Oggi pulsanti "Ho fatto la scheda A / B / altro allenamento" e contatore "2 su 3 questa settimana"; nel grafico settimanale il voto sotto ogni giorno.
